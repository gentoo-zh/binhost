# 已知风险与延后事项

分两类。**延后事项**是确认要做、尚未做的，每条写明谁负责、什么条件下解除、
何时之前处理；不做完不能从本文删除。**接受的风险**是权衡过决定不做的，改变
主意时把它移走并在提交里说明理由。

两类都不是「已修复」。站点与 README 的说法必须与本文一致。

## 延后事项

### 签名私钥暴露给建置阶段

负责人：Zakk。解除条件：编译与签名拆成两段，第二段不执行任何 ebuild 或其他
上游代码，并在建置机端到端验证。期限：下一轮线上验收完成之后立即开始，不与
其他工作并行。

`build/base-image.sh` 与 `build/build-container.sh` 都用 `--privileged` 起容器，
并把完整的 `GNUPGHOME` 挂进去。容器以 root 执行上百个第三方 ebuild 的建置代码，
其中任何一段被入侵都能读取或使用私钥。`docs/key-rotation.md` 末尾记的是同一件事。

在拆分完成之前不得声称私钥已受保护。

### 依赖闭包不执行完整解析

负责人：Zakk。解除条件：要么接入 Portage 的解析器，要么给出一份可审查的证明，
说明按索引匹配与解析器结论一致的边界在哪里。期限：私钥拆分之后。

`build/stage-index.py` 按索引自身匹配原子，不执行解析器。`||` 组取第一个索引能完整
满足的分支，没有这样的分支时整组不发，并记进 `unresolved.txt`。
`build/verify-deps.py` 按容器写出的 `installed.txt` 区分基础系统与真正缺失，
缺失的一律判不通过，但这只覆盖本站发布的内容，不等于执行过解析器。

在此之前，站点与 README 只能说本站不替代 Gentoo 官方 binhost，不得声称依赖完整。

### 下架失败时公开索引会返回 404

负责人：Zakk。解除条件：改成代际目录加一次切换，或给出别的顺序并说明为什么
它同时满足立即下架与可用性。期限：与代际切换一并处理。

`build/publish.sh` 在替换索引之前先删除 `quarantine.txt` 列出的产物。因为法律上的
立即下架优先于可用性，所以顺序是有意的。代价是随后的索引传输若失败，旧索引仍指向
已删除的文件，下游会拿到 404，直到下一轮建置。目前的补偿只有移除失败时整轮中止。

## 接受的风险

### 两个索引的替换不是一次原子切换

`build/publish.sh` 先留一份旧 `Packages`，`Packages.gz` 替换失败时还原，两个索引
不会长期停在不同代。仍然存在的是：两次 rename 之间进程被杀或主机重启，会留下不同
代；还原用的 `mv` 本身失败时没有第二层补救。

接受的理由是 Portage 只读其中一份，不会同时比对两者，而完整解法要改镜像机的目录
结构与 nginx 配置。这一条不涉及正确性，只涉及我们自己的检查在窗口内可能看到不一致。

### 站点同步不是一次原子切换

`deploy/publish-site.sh` 用一次 rsync 加 `--delay-updates`，更新集中到最后一起
rename，但 rename 阶段仍是逐个文件。中途失败可能留下不同代的 assets 与页面。
接受的理由与上一条相同。
