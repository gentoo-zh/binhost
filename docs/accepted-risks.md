# 已知风险与延后事项

本文分为两类。**延后事项**记录已经确认但尚未完成的工作，并注明负责人、解除条件
和期限；满足解除条件前不得删除。**接受的风险**记录经权衡后不处理的事项；若调整决定，
应移动对应条目，并在提交中说明理由。

两类都不表示问题已经修复。站点与 README 的表述必须与本文一致。

## 延后事项

本节负责人：Zakk。

### 依赖闭包不执行完整解析

解除条件：接入 Portage 解析器，或提交可审查的证明，明确索引匹配与
解析器结论一致的边界。期限：私钥拆分之后。

`build/stage-index.py` 按索引自身匹配原子，不执行解析器。`||` 组取第一个索引能完整
满足的分支，没有这样的分支时整组不发，并记进 `unresolved.txt`。

`build/verify-deps.py` 使用 emerge 前的基础系统快照，并按版本、slot、USE 与 repository
匹配完整 Atom。检查还使用本次 Gentoo binhost 索引的最小快照；剩余的无 USE 约束
原子可以由当前 Gentoo 与 gentoo-zh 源码仓库中的可见版本满足。一般源码包的
USE 配置未知，
因此带 USE 约束的原子不会由源码快照兜底。对于 `acct-group/*`、`acct-user/*` 与
`virtual/*`，源码快照按当前 ebuild 的 `IUSE` 默认启用项匹配完整 Atom。四个集合都
不满足的原子一律判不通过，但这不等于执行过完整解析器。

在此之前，站点与 README 只能说本站不替代 Gentoo 官方 binhost，不得声称依赖完整。

## 接受的风险

### 站点同步不是一次原子切换

`deploy/publish-site.sh` 执行一次 rsync，并使用 `--delay-updates` 与 `--delete-delay`。
接收与删除都延迟到传输结束，但 rename 阶段仍逐个处理文件。中途失败可能留下不同代的
assets 与页面。

接受的理由是站点目录同时存放每日任务生成的数据文件，改成代际目录需要一并搬动它们。
