FAQ

overlay

旧的 overlay 同步地址还可用吗？

2025 年 10 月起，Gentoo 官方不再为第三方仓库提供缓存镜像。此前添加的 gentoo-zh 仓库需更新同步源。旧的 microcai/gentoo-zh 地址会重定向到 gentoo-zh/overlay，手动设置过 remote 的用户也应更新地址。

配置步骤见 overlay 指南；背景见缓存镜像停用说明与仓库迁移记录。

distfiles

如何避免自动镜像某个软件包的 distfile？

ebuild 的 RESTRICT 中包含 mirror 或 fetch 时，会限制 distfiles 的自动镜像。bindist 只限制 binpkg，不单独决定 distfiles 是否镜像。

下载 distfile 时遇到 404，改用本站镜像能解决吗？

只有本站保存了所需文件时才能下载；本站只镜像 overlay ebuild 声明的 distfiles。GENTOO_MIRRORS 按顺序尝试地址，缺少文件时继续尝试后续地址。配置方法见配置 distfiles。

下载文件的大小或校验和与 Manifest 不符，怎么办？

上游可能替换了同一地址的文件，不能只重新生成摘要。circuitjs1-bin 曾出现这种情况，需要更新 ebuild 并实际构建、验证新版本。

binpkg

我该选 stable 还是 unstable？

按 Gentoo 主仓库的关键字选择：使用 amd64 选 stable，全局使用 ~amd64 选 unstable。两个频道都接受 gentoo-zh 的 ~amd64 软件包。频道配置见配置 binpkg；overlay 的关键字设置见 overlay 指南。

binpkg 应该配置在哪里？

本站使用 /etc/portage/binrepos.conf/gentoo-zh.conf 配置频道地址与签名验证。完整步骤见配置 binpkg。

OpenRC 和 systemd 都能使用吗？

能否使用取决于软件包的 USE 与依赖是否适合当前系统。两个频道均使用 desktop/systemd profile 构建，没有单独的 OpenRC 产物。USE 不匹配时，普通安装会改用可用的源码 ebuild。

本站提供哪些 binpkg？

本站发布构建机的整个 PKGDIR，包括收录的 overlay 软件包及从源码构建的 ::gentoo 依赖。发布前移除被 mask、受 RESTRICT=bindist 限制或继承 linux-mod 的 binpkg；acct-group、acct-user 与 virtual 不按类别排除。附带的依赖不替代 Gentoo 官方 binhost。可用软件包见包列表，纯文本清单见 stable 与 unstable。

包列表中的状态表示什么？

包列表分开显示公开索引、直接构建清单、当前发布政策和 distfiles 镜像状态。 同一行可以同时出现多个状态，因为它们说明不同事实。

状态触发条件与常见原因
✓公开 binpkg 索引已有该包，可以从本站下载。它不表示该包仍在直接构建清单。包名旁同时出现发布政策时，该政策针对当前 ebuild；公开的 binpkg 在发布前已按其版本与构建时的 USE 通过发布检查。
待构建该包是直接构建目标，但公开索引尚无 binpkg。它可能尚未完成首次构建，也可能最近一次未成功发布；该状态只表示目前没有公开产物。
不构建维护清单明确排除该包。常见原因包括无法构建、缺少支持或需要进一步核对再分发条件；标签提示中会显示记录的具体原因。
本频道不构建该包仍在共用收录清单中，但不符合当前频道的依赖或构建条件，因此本频道不直接构建。另一个频道仍可能发布该包。该包作为其他包的依赖构建时，本频道仍可能有它的 binpkg；这时 binpkg 列只显示勾号，排除原因在勾号的提示中。
清单外该包不是直接构建目标。上游已经提供预编译内容或构建收益较低时通常不会直接收录，但仍可能作为依赖随包发布；包名含 -bin 不会自动决定该状态。
不提供 binpkg当前 ebuild 的 RESTRICT 包含 bindist，因此本站不发布该包的 binpkg。源码包和上游预编译包都可能设置这项限制，常见原因是许可证、上游发布条款或预编译内容的再分发条件不允许本站分发二进制产物；包名含 -bin 本身不是判定依据。distfiles 是否镜像仍按 RESTRICT 中的 mirror、fetch 与每项 SRC_URI 单独判断。
许可证限制当前 ebuild 的 LICENSE 表达式不属于本站固定的 @BINARY-REDISTRIBUTABLE。许可证可能允许附带条件的再分发，但本站不会据此发布 binpkg；该状态与 RESTRICT=bindist 分开判定。
已移除overlay 已移除该包，但公开索引仍有它的 binpkg，仍可以下载。该行不链接到 overlay。
Distfiles —该包没有声明 distfile、RESTRICT 包含 mirror 或 fetch，或声明的文件尚未全部进入镜像。破折号提示会区分没有文件与不可用；该状态不表示 binpkg 不可用。

如何验证下载的 binpkg 来自本站且内容未被修改？

导入本站公钥，并使用配置中的 verify-signature = true 让 Portage 验证 binpkg 签名。公钥导入与仓库配置见配置 binpkg。

全局 FEATURES="binpkg-request-signature" 会覆盖 binrepos.conf 的验签设置，要求所有 binpkg（包括本地构建的）带有效且可信的签名。本地构建需启用 FEATURES="binpkg-signing"，并配置 BINPKG_GPG_SIGNING_KEY 与 BINPKG_GPG_SIGNING_GPG_HOME。

若用 getuto 在 /etc/portage/gnupg 创建的本地密钥签名，还须向 GnuPG 提供保存在该目录 pass 文件中的口令；默认签名命令不会自动读取该文件。

不安装 sec-keys 软件包时，如何取得签名公钥？

可以直接下载本站的公钥文件，无需安装 sec-keys 软件包。下载方式见公钥下载说明。

导入公钥时出现 no writable keyring found，怎么办？

getuto 须先建立 /etc/portage/gnupg 和 Portage Local Trust Key，再导入公钥。按配置第 1 步执行完整命令。口令由 --passphrase-file 从 /etc/portage/gnupg/pass 读取；验签以 portage 用户执行，因此须预先生成 trustdb。

配置之后 emerge 为何仍然从源码编译？

启用 binpkg 不保证每个软件包都能使用现有产物。USE 不匹配时，Portage 的普通安装会改用可用的源码 ebuild；依赖能否满足也取决于当前系统。先核对 getbinpkg 配置、频道与包列表；服务异常可查看服务状态。

binpkg 是否可能无法在我的 CPU 上运行？

仍有可能。两个频道使用 CFLAGS="-O2 -pipe -march=x86-64 -mtune=generic"，不使用 -march=native，但该设置不能改变 ebuild 附带的上游预编译对象或程序库。Portage 选择 binpkg 时不比较 CFLAGS，因此选用的 binpkg 不一定与 CPU 兼容。

Live ISO

Gig-OS 的使用说明在哪里？

Gig-OS 是其他组织的独立项目，本站及各镜像站只同步其安装镜像。启动、登录、硬件要求与问题反馈见 GitHub 上的 Gig-OS；镜像文件在 /gigos/ 目录。

镜像

中国大陆有哪些镜像，分别怎么配置？

可使用教育网联合镜像站、南京大学、南阳理工学院和河南教育网等镜像，地址见镜像列表。overlay 的 Git 仓库、distfiles 与 binpkg 需分别配置，见 overlay 指南、配置 distfiles 和配置 binpkg。

使用教育网联合镜像站时，为什么 Git 提示重定向？

教育网联合镜像站将请求重定向到就近的成员站，本身不保存文件。因此，Git 提示重定向是正常现象。

为什么各镜像的版本不一致？

各镜像按自己的计划同步，进度可能不同。某个镜像版本偏旧时，可换另一个镜像再同步；ISO 请选择对应目录中的最新版本。地址见镜像列表。

如何自行建立镜像？

本站文件的 rsync 地址是 rsync://distfiles.gentoozh.org/gentoo-zh/。同步与申请加入列表见自建镜像说明；overlay 的 Git 同步地址见 overlay 指南。
